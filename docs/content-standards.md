# Content Standards

## Quality and Depth

Notes must be accurate, beginner-friendly, structured for review, and free of unsupported completeness or exam-outcome claims. CPP sections explain definitions, purpose, basic benefits, use cases, pricing concepts, shared responsibility, and service recognition. SAA sections add architecture, integrations, resilience, performance, security, cost optimization, disaster recovery, and explicit trade-offs.

## Required Treatment

- Comparisons must use consistent criteria, state when each option fits, and avoid false absolutes.
- Shared Responsibility sections must distinguish AWS responsibilities, customer responsibilities, and service-model changes.
- Pricing sections should explain cost drivers and models without inventing prices or implying that volatile figures are permanent.
- Architecture sections should cover availability boundaries, failure behavior, scaling, security, integrations, and decision rationale where relevant.
- Exam tips and traps must teach reasoning, not claim leaked questions or unsupported exam percentages.
- References should prioritize current official AWS documentation, exam guides, FAQs, and pricing pages, with checked dates for volatile claims.

## Diagrams

Use Mermaid only when a relationship, flow, failure boundary, or architecture is materially clearer visually. Add explanatory prose, accessible labels, and no decorative diagram. Verify service names and connection directions.

Follow the general lesson template in [AGENTS.md](../AGENTS.md), but never add empty sections to awareness-level notes.
